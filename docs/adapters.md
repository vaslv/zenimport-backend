# Контракт адаптера банка

Реестр расположен в `extension/extract.js`. Каждый адаптер реализует `id`, `version`, `detect()` и `extract()` и работает в isolated world на текущей вкладке после нажатия иконки.

## Определение и извлечение

- Проверяйте точный hostname, путь и ожидаемую структуру страницы. Не используйте `hostname.includes(bankName)`.
- Извлекайте только отображённые строки и идентификатор конкретного счёта. Если номер скрыт до неуникальных четырёх цифр, нужен отдельный стабильный alias, согласованный с пользователем.
- Виртуализированный список/пагинация: расширение не считает незагруженные строки. До реализации явного обхода показывайте это ограничение.
- Банковский reference обязателен. Не заменяйте его хешем суммы/даты: две одинаковые покупки могут быть разными.
- Парсите дату и сумму по установленному формату банка. Не используйте эвристику «удалить все нецифры»; она теряет знак и десятичную часть.
- Передавайте signed amount_minor как безопасное целое. Для VND scale=1, USD/EUR scale=100. Не используйте floating point для нормализации центов.
- Pending/hold, переводы и неизвестные типы не смешивайте с обычными проводками. Новый адаптер должен отклонять неподдержанные типы с понятным сообщением до импорта.
- Пакет содержит от 1 до 2000 операций, общий HTTP body не более 2 МБ. При ошибке одной строки весь сбор должен остановиться.

## Требование исторического сбора

Текущий demo-адаптер читает загруженную таблицу. Для реальных банков требуется история за выбранный период: сбор нескольких страниц/частей с накоплением, продолжением после прерывания и дедупликацией пересекающихся периодов. Автоматизация переходов внутри авторизованной страницы либо ручная загрузка частей пользователем выбирается после изучения конкретного банка. Доступ к незагруженной истории не предполагается автоматически.

В будущем контракте сессии импорта нужны запрошенный период, фактически наблюдённые даты, обработанные части/страницы, число операций и явный статус полноты. Первый и последний день среди строк не доказывают отсутствие пропусков. Лимит 2000 строк/2 МБ относится к одному текущему HTTP-пакету; большая история должна передаваться несколькими пакетами с сохранением прогресса.

Для последующей категоризации потребуется добавить в строгие модели получателя, назначение и другие реально доступные поля, например MCC. Сейчас RawRow содержит только reference/date/amount/description; новые поля нельзя отправлять без соответствующего изменения моделей backend. Исходное значение получателя и его нормализованное представление следует хранить раздельно.

## Исходные данные и debug

Allowlist RawRow: reference, date, amount, description, все как видимые исходные строки. Сохраняются версия адаптера, bank, account, currency. HTML, cookies, localStorage, session tokens и сетевые заголовки не входят в контракт; лишние поля отклоняются сервером.

Кнопка debug сохраняет тот же пакет локально как JSON с явным подтверждением пользователя. Полный HTML intentionally не реализован даже в debug MVP; для разработки реальных адаптеров используйте отдельно подготовленный, обезличенный fixture только нужной таблицы. Не пересылайте полный DOM страницы интернет-банка.

## Как добавить банк

1. Зафиксировать домен, форматы, отображение debit/credit, стабильный reference и идентичность счёта.
2. Добавить адаптер в реестр и обезличенные fixtures.
3. Покрыть расходы/доходы, пустую таблицу, неизвестный формат, повторяющиеся суммы, валюты, pending, неверный hostname и изменённую разметку.
4. Проверить вручную на загруженной странице банка без отправки; сравнить debug JSON с видимыми строками.
5. Пройти demo backend, затем согласованный живой импорт.

Сейчас включён только `demo`, точные адреса localhost/127.0.0.1 с путём `/demo-bank`. Это тестовый адаптер, не Vietcombank и не другой настоящий банк.
