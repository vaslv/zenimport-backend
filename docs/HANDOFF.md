# ZenImport — продолжение в Codex

Основная рабочая папка: `/Users/vaslv/Projects/Vaslv/ZenImport`. Копии и ZIP в старом чате не являются актуальным проектом. Прочитать `docs/TASK.md`, `docs/PLAN.md`, `README.md`, `docs/architecture.md` и `docs/adapters.md`.

## Последний согласованный порядок

1. Docker-запуск и контейнерные тесты.
2. Интерфейс расширения Chrome с локальным backend.
3. Исследование API ZenMoney: качественная готовая библиотека либо отдельный клиентский пакет.
4. Проектирование БД и загрузка всех доступных согласованных данных/истории ZenMoney.
5. История банков, отдельные банковские таблицы.
6. Сопоставление и подсказки категорий по историческим примерам.
7. Только после этого — запись новых подтверждённых операций в ZenMoney.

Не путать реализацию будущих этапов с проверкой уже существующего демонстрационного каркаса. Живую запись до этапа 7 не выполнять. История и категоризация остаются обязательными; глубина истории и банки пока не названы.

## Состояние проекта

Есть FastAPI/Pydantic, SQLite WAL, предварительный клиент HTTPX, MV3 popup и отдельная SPA без сборки. В интерфейсе пока рабочее имя ZenBridge. Есть demo-адаптер, импорт, временное JSON-зеркало, matching и outbox. Эти части — прототип, а не утверждённая окончательная модель БД или клиент API.

Добавлены и проверены Dockerfile с runtime/test targets, Compose, отдельный тестовый проект, генератор `.env` и проверка сохранности данных при пересоздании контейнера. Фактические результаты — в `docs/acceptance.md` и README; не утверждать успех проверки без записи результата.

В Docker прошли 14 backend-тестов, 3 parser-теста, HTTP smoke и проверка отдельного Compose-сервиса после пересоздания. Backend оставлен в DEMO на http://127.0.0.1:18791. Следующий этап — интерфейс Chrome Extension. Полный интерфейс в Chrome и живой ZenMoney не проверялись. Реальных банковских адаптеров нет. Vietcombank был только примером прежнего обсуждения.

## Правила работы

- Общаться по-русски. Не создавать теги и не выполнять push без отдельного явного разрешения пользователя.
- Использовать Docker для основной локальной проверки; `.venv` остаётся вспомогательным окружением.
- Не читать и не выводить секреты `.env` в чат; не включать токены, БД и debug-файлы в образы.
- Банковский HTML, пароли и cookies не передавать обычным импортом.
- Docker-данные DEMO/LIVE и одноразовые тестовые данные разделены. Не удалять обычные тома ради теста.
- Проверять текущую документацию API/библиотек через Context7, при отсутствии — официальный источник.
- Не переписывать skeleton без обоснования. Выбор готовой библиотеки/отдельного пакета ZenMoney должен предшествовать окончательному проектированию БД.
- Исторический импорт сам по себе не разрешает добавлять старые операции обратно в ZenMoney.

## Сообщение для продолжения

Продолжи ZenImport. Прочитай docs/HANDOFF.md, docs/PLAN.md, README.md и docs/acceptance.md. Проверь фактический статус этапа Docker и заверши его, если остались проверки. После него начни этап 2: интерфейс расширения Chrome, подключённый к локальному backend в Docker. Соблюдай дальнейшую очередность: выбор клиента API ZenMoney, схема и история ZenMoney, банковские данные, сопоставление и категории, и только затем live-запись. Не выполняй push и не создавай теги без отдельного разрешения.
