# Работа на странице банка — 0.17.0

Основной интерфейс находится в строках истории VietinBank. В меню расширения
остались переключатель **«Расширенный интерфейс»**, настройки и одна кнопка
**«Синхронизировать»** с количеством недостающих записей выбранного счёта в локальной истории.

## Строка операции

Слева — небольшой значок статуса (`✓` — есть в ZenMoney, `+` — новая,
`?` — нужно выбрать соответствие, `!` — результат отправки требует проверки).
Дальше четыре круглые кнопки: расход `−`, приход `+`, трансфер и долг.
Выбранная кнопка залита коралловым цветом, остальные прозрачные. Названия
доступны в подсказке и для экранного диктора; переключать тип можно клавишами
стрелок. Направление банковской суммы ограничивает доступные типы.

Остальная ширина отдана полям выбранного типа. Предполагаемые категории
расположены ссылками под выбором категории; длинный список переносится на
следующую строку, без горизонтальной прокрутки. Поиск появляется при открытии
списка категорий.

Наблюдатель хранит в памяти страницы последний очищенный ответ банка и может
повторно передать его интерфейсу. Это восстанавливает импорт, когда ответ пришёл
до перехода SPA в историю или временно не удалось сохранить его на сервере.
Повторная обработка не создаёт дубли и не отправляет записи в ZenMoney.
При смене счёта чужой ответ не применяется. Полный HTML, токены и банковская
сессия в этот буфер не попадают. После обновления расширения нужно перезагрузить
банковскую страницу, чтобы наблюдатель получил её начальный ответ.

## Сценарий

1. Включите переключатель и откройте историю нужного счёта. Расширение читает
   уже сохранённые данные, автоматически получает актуальные данные ZenMoney
   и наблюдает ответы истории банка. Вход в банк выполняется вручную.
2. Категория нового получателя не выдумывается. Однозначные подсказки назначаются
   по прежним подтверждённым примерам: минимум три с одной категорией, без
   противоречащих примеров; также действуют явно сохранённые правила получателей.
3. Кнопка **«Синхронизировать»** получает **шесть месяцев истории** выбранного
   счёта, проходя все интервалы и страницы. После полного сбора обновляет данные
   ZenMoney и отправляет все недостающие операции **сохранённой истории этого
   счёта**, включая ранее загруженные более старые записи и записи без категории.
   Списания становятся расходами, поступления — приходами; выбранные тип и
   категория сохраняются. Пакеты — до 20 записей. Спорные соответствия остаются
   для сверки; неподтверждённая отправка останавливает дальнейший цикл. Меню можно
   закрыть. Нулевой счётчик не блокирует получение новых банковских данных.
4. До первого создания выбор категории/типа сохраняется локально. После создания
   выбор категории или заполненного типа автоматически отправляет **одну**
   существующую запись с тем же UUID. Для перевода сначала нужны второй счёт и,
   если валюты различаются, сумма; для долга — человек. Текстовые параметры
   сохраняются при завершении ввода (выходе из поля). Общего окна подтверждения
   для этих отдельных изменений нет: выбор является командой на обновление.
5. Зелёная галочка означает наличие записи в ZenMoney, оранжевый плюс — новую
   банковскую операцию. Красный знак сообщает о неоднозначном соответствии или
   неподтверждённой отправке. Категорию видно в соседнем поле.

Переключатель действует и в уже открытых вкладках: выключение удаляет элементы,
останавливает чтение истории и продление банковской сессии. Включение возвращает
элементы без перезагрузки. Если расширение установлено/обновлено после открытия
истории, перезагрузите банковскую страницу один раз, чтобы наблюдатель мог
получить полный новый ответ банка. Токены остаются в service worker.

## Проверка и восстановление

Каждая запись проходит получение свежих данных, проверку снимка, сохранение
намерения в БД перед запросом и отдельную проверку фактического результата.
Потеря ответа не запускает слепой повтор. Настройки открывают существующий
ZenImport, где остаются сверка, проверка результата и явная повторная подготовка.
Ссылка **«История и диагностика»** в настройках открывает прежние инструменты
(`tools.html`), включая загрузку длительной истории и диагностический отчёт.

Другие страницы ZenImport пока сохранены и продолжают использовать прежние
локальные черновики и общий просмотр перед отправкой. Их переработка — отдельный
этап. Локальная БД хранит историю для подсказок и связи/намерения для защиты от
дублей; миграции или удаления существующих финансовых данных не требуются.

Backend принимает необязательный `bank_ids` в области подготовки/отправки
новых операций (1–200 идентификаторов). Фильтр действует также при создании
локальных записей. Проверка принадлежности счёта, кандидатов совпадения и
неопределённых ранее отправленных записей остаётся обязательной.

## Компактная банковская строка — 0.15.0

Каждой банковской операции соответствует одна строка ZenImport: значок наличия
в ZenMoney, тип и поля выбранного типа. Галочка означает наличие связанной записи
в ZenMoney, независимо от заполнения категории; «+» — новая запись, «?» — возможная
пара, «!» — неподтверждённая отправка. Разъяснение доступно в подсказке значка.

Основных типов четыре: «Расход», «Приход», «Трансфер», «Долг». Расход/приход
показывают поиск категории и приоритетные подсказки. У прихода в третьем блоке
также доступен «Возврат покупки», чтобы сохранить работу с расходными категориями.
Для долга выбирается действие и человек: для списания «дать/вернуть», для поступления
«взять/получить возврат». Для трансфера выбирается второй счёт и при разных валютах
точная сумма на нём. Направление и сумма банковского движения не меняются.

Категория и тип у настоящих возможных совпадений доступны для локального
сохранения, но создание новой записи блокируется до решения соответствия.
Нажатие «?» открывает список кандидатов: выбранная запись связывается локально,
без отправки изменения в ZenMoney. Следующий выбор категории/типа изменяет
уже эту связанную запись. Для составной группы галочка открывает выбор части,
позволяя редактировать одну часть и сохранять одну строку интерфейса.

Запись ZenMoney, уже связанная с другой банковской операцией **того же счёта**,
исключается из кандидатов нового платежа. Вторая сторона перевода на другом
счёте продолжает сопоставляться с тем же UUID. Массовое сведение проверяет общий
снимок до сохранения и обновляет доступные кандидаты после каждой своей связи.

## Навигация внутри банковского приложения — 0.16.1

История может открываться без перезагрузки исходной страницы банка. Worker проверяет
банковский origin отправителя, верхний фрейм, текущий URL вкладки и счёт. Дополнительно
запрашивает текущий счёт у того же content document через `documentId`; старый документ
после перезагрузки не подтверждает запрос. Перед записью контекст проверяется повторно
после чтения БД. Исходный `sender.url` не используется для определения текущего маршрута.

Если синхронизация недоступна, меню показывает конкретную причину: подключение,
API-токен, привязка счёта или текущая страница. Причина обновляется автоматически и
очищается после восстановления.
