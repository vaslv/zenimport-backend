# B1: происхождение и карта модулей

Исходный проект: ZenImport, commit `f3b283894872e0e0e732a817a2ada8928f73489a`.
Новый: ZenImportBackend. Создан `git clone --no-local --no-hardlinks`, remote origin удалён. Исходный репозиторий и работающий контейнер не менялись при выделении. История доступна локально через `git show f3b2838:backend/имя.py`; финансовые данные/`.env` не клонировались, поскольку не были отслеживаемыми файлами.

## Решения по старому runtime

| Прежний модуль | Решение | Дальнейшая ответственность |
|---|---|---|
| sync_contracts.py | Перенесён | Модели API v1; B1 добавляет только коды ошибок internal_error/method_not_allowed |
| config.py | Заменён; create_env сохранён | Явный абсолютный путь, разделённые секреты, безопасная генерация конфигурации |
| app.py / __main__.py | Заменены | Самостоятельный API/lifespan; только health/info на B1 |
| db.py | Заменён bootstrap storage.py | Финансовая схема/перенос — B2. Старый initialize автоматически не вызывается |
| creation.py | Только архив в Git; заменяется в B5 | Постоянный UUID, очередь, независимая проверка результата; без preview/ручной сверки |
| zenstore.py | Только архив; замена в B2/B4 | Точные проекции, неизвестные поля, сырой diff, cursor и удаления; источники сведений о старой схеме сохранены в docs/zenmoney-storage.md |
| link_groups.py | Только архив; данные сохраняются в B2 | Подтверждённые связи 1:N/N:M остаются историей, UI сопоставления не возвращается |
| reconciliation.py | Только архив; пригодная логика переносится после проверки в B4 | Идентификация получателя и подтверждённые примеры, без блокировки спорных новых записей |
| category_drafts.py / category_send.py | Только архив | Старые правки существующих ZenMoney-записей архивируются; нет новой отправки локальных правок |
| operations.py | Только архив | Редакторы типов/долгов/переводов убраны; пользователь работает в мобильном ZenMoney |
| service.py / day_review.py / splits.py / batch_send.py / exclusions.py | Только архив; обязанности переопределяются B2–B5 | Приём, постоянные исключения и доставка без редактора/сверок |
| zenmoney.py / jsoncodec.py | Только архив; SDK используется напрямую | Клиент жизненного цикла уже в app.py; при B4 точная сериализация берётся из SDK |

«Только архив» означает отсутствие модуля в рабочем дереве/runtime; его код остаётся в Git. Прежде чем удалять, проверены импорты/функции и назначение сохранённых таблиц. B1 не заявляет перенос финансовой логики: таблицы, архивы, исключения, UUID и связи будут проверены на B2/M1. Нельзя переносить прежний отправитель целиком — он применяет пользовательские правки и содержит старые проверки кандидатов.

## Новые границы

Сейчас: HTTP/config/storage bootstrap/модели. На B2 добавляются финансовое хранилище и явные миграции; на B3 — настройки и приём страниц/планирование; на B4 — зеркало и обучение; на B5 — долговечная доставка. Это модули одного сервиса, без дополнительных микросервисов, брокера или изменения СУБД.

Из Docker удалены browser/parser targets, HTML demo и зависимость от extension. Контекст сборки разрешает только нужные backend/vendor/test/config файлы. SDK wheel проверяется SHA256 и устанавливается из vendor; исходник SDK не требуется.

На B1 новая БД получила application_id `0x5A494231`, schema 1 и service_meta/instance_id. B2 добавил финансовую схему **2**, приватный backup и транзакционное обновление собственной v1. Старую/чужую/будущую схему сервис по-прежнему отвергает до изменений. Legacy v12 конвертируется явно в новый файл: [financial-storage.md](financial-storage.md). Рабочая БД не переносилась.

B3 добавил [приём истории и настройки](capture.md): accounts/capture/capture_policy/sync_api,
схему **3** и upgrade своей v2. Задания/снимки/страницы теперь работают через HTTP;
старые редакторы/сверки не возвращались. B4 добавил mirror/predictions и схему **4**;
SDK читает актуальные данные, прогноз использует независимые подтверждённые
платежи. См. [mirror-predictions.md](mirror-predictions.md). B5 добавил delivery.py, схему **5**, независимый worker, durable intent и проверку UUID без перезаписи мобильных изменений: [delivery.md](delivery.md).

B6 добавил snapshot.py и независимый прогон обеих архитектур/контейнерного
восстановления: [b6-validation.md](b6-validation.md). Эксплуатация —
[operations.md](operations.md); E5 требует нового расширения.

## Контракт B0 → B1

Реализованы GET /health и GET /api/v1/info, общий Bearer/auth, лимит тела и форматы ошибок. Маршруты B3 и отправитель B5 реализованы. Swagger/HTML и старые mutating endpoints не обслуживаются. Наличие токена не доказывает свежесть: B4 показывает ready только после успешной актуализации SDK, не старше 300 секунд. Ошибка конфигурации приводит к отказу запуска, не к созданию демо-базы.
