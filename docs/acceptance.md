## Ограничения

- Установленное расширение в Chrome ещё не прошло UI-приёмку: это этап 2.
- Готовая библиотека или отдельный пакет ZenMoney пока не выбраны. Текущий HTTP-клиент предварительный.
- JSON-зеркало не является окончательной структурой БД всех сущностей API.
- Живой ZenMoney, настоящие банки, историческая полнота, подсказки и live-запись не проверялись.
- Проверена ARM64-сборка. AMD64-сборку и серверное развёртывание следует проверить в выбранном окружении; multi-architecture базовые образы сами по себе не доказывают такую приёмку.
- В тестах остаётся upstream deprecation warning TestClient/httpx; ошибок тестов нет.
- Для сборки из ограниченной среды Codex использовался отдельный writable каталог BUILDX_CONFIG в рабочей области, поскольку стандартный каталог Docker Buildx был недоступен для записи. В обычном пользовательском терминале дополнительная настройка не требуется.

Git push, создание тегов, публикация образов и развёртывание на удалённый сервер не выполнялись.

## Этап 2 — расширение и локальный backend, 5 октября 2026

Полный `scripts/test-docker.sh`: 15 backend-тестов, 3 JS-теста, HTTP smoke, сохранность после пересоздания контейнера и 3 браузерных теста — PASS. Настоящее unpacked MV3 расширение загружается в Chromium Playwright 1.58.0 внутри Docker. Проверены popup → активная вкладка → локальный разбор → импорт → повтор без дублей; SPA → синхронизация → привязка → demo-confirm/send; настройки, неверный токен, недоступный backend, восстановление соединения и неподдержанный сайт. Content script не может прочитать токен из storage. Скриншоты desktop 1440×1000 и mobile 390×844 просмотрены; горизонтальной прокрутки нет.

Скриншоты сохраняются в `test-results/`, исключённой из Git. Тестовый сервер и данные изолированы от обычного запуска. Это автоматическая проверка Chromium, а не ручная проверка установленного пользовательского Google Chrome. Live-confirm/send заблокированы сервером; demo-отправка не обращается в ZenMoney.

## Этап 4 — структурированная история v2

Полный финальный Docker-прогон: **47 Python-тестов + 3 parser-теста + 4 browser-теста — PASS**. Дополнительно прошли HTTP smoke и пересоздание контейнера с сохранением данных/очереди. Проверены все 11 коллекций, неизвестные поля/коллекции в архиве, точный Decimal, nullable составной бюджетный ключ, инкременты, удаления, soft delete, повтор, откат частичного ответа и прерывания, миграция v1→v2, повтор миграции и запрет будущей схемы. Мигрированное зеркало повторно запрашивает все коллекции; при сетевой ошибке сохраняется флаг повторной загрузки.

API истории проверен на 1 200 операциях: пределы страниц, отсутствие пересечения соседних страниц, даты/счёт, неверный диапазон и авторизация. Четвёртый browser-тест проверяет UI страниц/фильтра на подменённом HTTP-ответе из 105 записей; backend для этого сценария отдельно проверен предыдущим тестом. Остальные браузерные сценарии работают с настоящим Docker backend и установленным MV3.

Обычный локальный сервис пересобран, healthy в DEMO на http://127.0.0.1:18791. Авторизованный /api/state подтверждает schema_version=2; SQLite integrity_check=ok. База этого обычного сервиса не содержала банковских операций при проверке после запуска. Создан и проверен локальный снимок уже обновлённой БД `data/backups/v2-20261005.sqlite3` (игнорируется Git); это не резервная копия до миграции. Сквозная сохранность непустой базы проверена в изолированных тестах.

Этап 4 завершён по реализации и fixture-тестам, но не принят по фактической полноте пользовательской истории. Токен/реальная выгрузка и согласованный период отсутствуют. Этапы 5–7 не объявляются готовыми: неизвестны три банка/домены/структура истории. Реальных финансовых записей в ZenMoney не выполнялось.
