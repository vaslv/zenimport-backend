# Самостоятельный SDK и интеграция backend

Обновлено 14 октября 2026. ZenImport использует `zenmoney-api-client` **0.6.0**
из соседнего самостоятельного проекта `../ZenMoneyAPI`. В `vendor/` хранится
проверенный wheel из ревизии SDK `52ffbc7`; Docker проверяет SHA256SUMS.
Обычная сборка ZenImport не требует соседнего checkout или исходников SDK.

Backend импортирует только `zenmoney_api`: Client, protocol, transactions.
Старый namespace `zenimport_zenmoney`, прикладной HTTP-адаптер и wheel 0.4 удалены.

- SDK отвечает за HTTP, Bearer, diff/suggest, JSON с Decimal, модели, builders,
  ошибки и владение соединениями. В нём нет БД, банков и правил review.
- Backend отвечает за SQLite, курсор, архивирование, привязки счетов, обучение
  категорий, подтверждение и проверку фактической записи.
- DemoClient — автономный тестовый источник с тем же read_diff/upsert интерфейсом;
  он не используется для LIVE.
- Chrome и банковские адаптеры используют прежние HTTP endpoints backend.

## Контракт приложения

`Client.read_diff(cursor, force_fetch=...)` — получение;
`Client.upsert('transaction', payloads, cursor)` — явная запись после просмотра.
Смешанная отправка новых операций, категорий и изменений типов — один upsert со всеми объектами.
Ответ записи не считается подтверждением и не используется как sync cursor;
следует отдельное чтение. Ошибка соединения может возникнуть после применения
запроса. Intent и UUID сохраняются до сети, автоматического повтора записи нет.

Расходы/приходы готовятся через transactions.expense/income, изменение категории —
через transactions.update полного полученного объекта. Суммы не проходят через
float. Библиотека получает все необходимые nullable/default поля создания.

Один синхронный Client принадлежит приложению; endpoints выполняются в thread pool,
сетевая синхронизация/отправка сериализуется существующим lock. Lifespan закрывает
созданный приложением Client. За внедрённый извне клиент отвечает вызывающая сторона.
Bearer-токена достаточно; OAuth-регистрация не требуется.
