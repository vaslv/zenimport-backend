# Единый список и локальная сверка — 0.3.0

Основной экран расширения — «Операции». Один список **банковских** операций,
новые даты сверху, группы по дням, суммы справа, доходы зелёным. Категория,
подпись счёта и спокойная палитра с коралловым акцентом ориентированы на предоставленные
скриншоты ZenMoney. Полная история ZenMoney остаётся отдельной вкладкой;
записи, имеющиеся только в ZenMoney, не добавляются в банковский список.

Фильтры: связанный счёт, даты, поиск по получателю/описанию, Все / Уже в ZenMoney /
Новые / Проверить. Показывается по 100 строк, остальные — кнопкой «Показать ещё».
Фильтрация выполняется по всему загруженному банковскому списку, до отображения
первых 100 строк. В строке раскрываются кандидаты, основание категории и исходные поля.

## Совпадения

Кандидат: тот же связанный счёт, точная сумма с направлением и дата ±2 дня.
Удалённые и hold-записи исключаются. Это **не автоматическое подтверждение**, даже
если кандидат один: статус «Проверить совпадение». Пользователь выбирает
«Это та же операция», после чего локально сохраняется linked_id и отображается
«Уже в ZenMoney». Подтверждение сверяет полный список кандидатов с показанным,
запрещает повторное использование одной записи ZenMoney другой банковской строкой.

Новый endpoint POST /api/review/{id}/link принимает action=link, match_id,
reviewed_candidates. Иные действия отклоняются. Он доступен LIVE, но **никогда
не вызывает ZenMoney API и не создаёт outbox**. DELETE /api/review/{id}/link отменяет
только локальную связь, возвращая pending. Это не удаляет операцию ZenMoney.
Сверка проводится по локальному зеркалу; «Синхронизировать ZenMoney» обновляет его
отдельно. Устаревшая/исчезнувшая связанная запись получает «Связь изменилась».

Отсутствие кандидатов означает «Новая» относительно локальной истории, а не гарантию
отсутствия дубля на сервере. Ранее реализованная отправка работает только в DEMO;
LIVE-создание и отправка остаются заблокированы. Ручные связи не подтверждаются
агентом автоматически во время разработки.

## Категории

Для новой строки подсказка строится из более ранних записей того же счёта и направления:

1. Точное нормализованное имя банковского получателя равно payee ZenMoney.
2. Подтверждённые связи с тем же банковским получателем (приоритет ключа — реквизит,
   затем имя). Если реквизита/имени нет, используется полностью совпадающее описание.
   Идентификаторы внутри описания не вырезаются, не применяется нечёткое сравнение.

Нужно не менее двух независимых примеров; id примеров дедуплицируются. Подходят лишь
неудалённые, неотложенные, обычные доходы/расходы с одной активной категорией.
Переводы, смешанные движения, записи из будущего и неподтверждённые банковские кандидаты
не обучают правила. Одинаковое описание комиссии и покупки не предполагается.

Если категории противоречат друг другу, автоматической подсказки нет: показываются
распределение и примеры. Если все согласны — категория отмечена как предположение,
с числом примеров и раскрываемым основанием. Это не сохранённое/принятое правило и
не разрешение отправлять запись. Отмена связи или изменение зеркала пересчитывает
подсказки. Произвольное банковское содержимое выводится textContent, не исполняется.

## Проверка

Backend-тесты проверяют LIVE link/unlink без удалённых вызовов, запрет create/send,
устаревший список кандидатов, повторное присвоение записи, исчезнувшую связь, область
обучения, конфликты категорий и точное описание карточных операций. Браузерный тест
проверяет группировку, фильтры, раскрытие основания, подтверждение/отмену, отсутствие
LIVE-создания и HTML-инъекции; сохранены десктопный и мобильный снимки в test-results.

## Сверка целого дня, 0.3.1

В API state поле `day_review` содержит сверку полного локального набора операций каждого
банковского счёта за календарный день. Проверяется равенство количества и мультимножества
сумм со знаком по соответствующему счёту ZenMoney; переводы учитываются движением по счёту.
Фильтры и пагинация интерфейса не влияют на расчёт. Равенство относится к загруженным
данным: до подтверждения необходимо убедиться в полноте истории банка и обновить зеркало
ZenMoney. Равенство сумм само по себе не доказывает полноту обоих источников.

Уникальные суммы дают пары. Уже подтверждённые связи исключаются из оставшихся пар;
повторяющиеся суммы без уникального соответствия требуют ручной проверки. Предложения
ничего не изменяют до нажатия «Подтвердить пары дня». POST
`/api/review-days/{bank_account}/{date}/confirm` принимает snapshot предложения,
повторно вычисляет сверку и атомарно создаёт локальные связи. Изменившийся snapshot,
архивный/невалидный счёт и повторное использование записи ZenMoney отвергаются.
Отменять связи можно пооперационно. Записи в ZenMoney и outbox не создаются.

`recipient_profiles` — представление базы получателей по сохранённым подтверждённым
связям: получатель + банковский счёт + направление → список категорий с числом примеров.
Это производные данные, а не отдельная копия истории: отмена/изменение связи немедленно
меняет профиль. Ключ — точный счёт получателя, затем точное имя, затем полное описание;
похожие строки автоматически не объединяются. Переводы и записи с несколькими тегами
не служат примерами категории. Одна категория с >=2 примерами даёт уверенную подсказку;
несколько категорий показываются как неоднозначность, даже если одна преобладает.
Подсказки новым операциям используют только более ранние примеры. Профиль целиком
показывает всю подтверждённую историю. Предложенная категория не считается принятой
и не становится обучающим примером. LIVE-подтверждение категории для новой записи и
её отправка остаются следующим этапом; сейчас доступны исторические связи и подсказки.

## Массовое подтверждение истории, 0.3.2

Кнопка «Сопоставить все однозначные дни» подтверждает только дни `bulk_eligible=true`:
количество и все суммы совпадают, счёт валиден, нет неоднозначных оставшихся пар,
необработанных конфликтов или конкурирующих банковских счетов на одну запись ZenMoney.
Если в дне есть сомнения, весь день исключается из массового действия, включая его
уникальные пары. Пооперационная и отдельная дневная сверка остаются доступны вручную.

Область действия — выбранный банковский счёт (либо все) и границы дат; поиск, фильтр
статуса и пагинация списка не ограничивают пакет. Рядом с кнопкой показаны количество
дней/операций и раскрываемый список дней. Один клик — одно явное локальное подтверждение.
Никаких связей при открытии страницы не создаётся.

POST `/api/review-days/confirm` принимает `days: [{bank_account, date, snapshot}]`.
Под одним lock и SQLite-транзакцией весь пакет проверяется по свежей локальной сверке,
и только затем создаются связи. Устаревший/повторный snapshot, повтор дня или сомнительный
день отклоняют весь запрос; при ошибке все изменения откатываются. API никогда не
расширяет переданный список дней автоматически. Отмена доступна для каждой связи.
Источником истины остаются импорт банка и локальное зеркало ZenMoney: перед массовой
сверкой загрузите полную историю и обновите зеркало. Записи в ZenMoney не отправляются.
