# ZenImport Backend

Самостоятельный Docker-сервис для получения банковской истории из Chrome и добавления новых операций в ZenMoney. Код расширения и checkout SDK для сборки не нужны: проверенный wheel SDK 0.6.0 включён в `vendor/`.

**Текущий этап B1:** самостоятельный runtime, конфигурация, SQLite bootstrap, health и проверка совместимости API. Приём банковской истории, финансовые таблицы, зеркало и очередь появятся на B2–B5. Эта версия не заменяет рабочий ZenImport и не отправляет операции. Старое расширение пока к ней не подключать.

План: [docs/refactor/README.md](docs/refactor/README.md). Состояние: [docs/refactor/05-progress.md](docs/refactor/05-progress.md). Контракт: [docs/sync-api-v1.md](docs/sync-api-v1.md). Решения о переносе старых модулей: [docs/extraction-map.md](docs/extraction-map.md).

## Локальный запуск

Нужны Docker Engine и Compose. Python/Node на компьютере не требуются.

```sh
# Только если .env ещё нет:
docker compose --profile tools run --build --rm --no-deps --user "$(id -u):$(id -g)" init
# После проверки настроек:
docker compose up --build -d --wait backend
```

Генератор создаёт `.env` с правами 600, случайным `API_TOKEN` и явными настройками. Существующий файл не перезаписывается; токен не печатается. `API_TOKEN` — для подключения расширения, `ZENMONEY_TOKEN` — только для сервера. В B1 токен ZenMoney можно оставить пустым. Compose читает `.env`; приложение само файлы конфигурации не разыскивает.

Сервис доступен на `http://127.0.0.1:18792`, отдельно от прежнего порта 18791. Токен backend минимум 24 символа, без пробелов. `DATABASE_PATH` — абсолютный путь **в контейнере**, по умолчанию `/data/zenimport.sqlite3`. Для данных используется отдельный именованный том `DATA_VOLUME=zenimport-backend-data`; имя сохранено в `.env` и не зависит от каталога запуска. Один процесс/один экземпляр backend.

| Запрос | Ответ |
|---|---|
| GET `/health` без токена | 200, если хранилище доступно; иначе 503 |
| GET `/api/v1/info` с Bearer API_TOKEN | Версия, ограничения запросов, состояние подключения |
| Остальные бизнес-маршруты v1 | Ещё не реализованы на B1 |

`not_configured` означает отсутствие серверного токена ZenMoney. При заданном токене B1 возвращает `unavailable` и пустое время актуализации: без реализованного B4 наличие токена не доказывает получение свежих данных. Служебные запросы B1 вообще не вызывают настоящий API ZenMoney. Отдельных HTML-страниц/Swagger/редактора нет.

```sh
docker compose logs --tail 50 backend
docker compose down
```

Обычный `down` сохраняет именованный том. После изменения конфигурации пересоздайте контейнер через `up -d --force-recreate --wait backend`. Не меняйте имя тома при обычном обновлении — это подключит другую базу.

## Размещение на сервере

Перенесите этот проект либо собранный образ на нужную машину; собирайте для архитектуры этой машины. Один и тот же Dockerfile/Compose используется локально и удалённо. Настройки задаются при запуске, в образе секретов нет. Публикация образа в registry не обязательна.

На сервере оставьте HTTP-порт привязанным к loopback и настройте свой HTTPS reverse proxy на `127.0.0.1:18792`. Расширение будет использовать внешний HTTPS-адрес и отдельный API_TOKEN. Токен ZenMoney в расширение не передаётся. Требуются постоянное локальное хранилище Docker и резервное копирование; несколько экземпляров сервиса/сетевой общий SQLite-том не поддерживаются.

B1 не подключает том старого приложения: база с чужим application_id/схемой отвергается **до изменений**. Подготовка переноса существующих финансовых данных — B2/M1. Для backup используйте согласованный SQLite backup либо остановите сервис и сохраните весь том с WAL; копирование только основного файла работающей SQLite не является надёжным backup.

## Проверки

```sh
scripts/test-docker.sh
```

Скрипт задаёт искусственный токен и уникальные имена Compose-проекта/тома, не читает `.env`, не публикует порт и не использует рабочую БД. Проверяет конфигурационный образ без сети, unit/контрактные тесты без сети, настоящий HTTP-сервис во внутренней тестовой сети и сохранность identity БД после пересоздания контейнера. Проверяется установленный vendored SDK с fake HTTP, без соседней библиотеки. Удаляет только собственное тестовое окружение.

Тестовый override требует Compose с поддержкой `!reset`. Отдельно можно выполнить `scripts/test-contracts.sh`. Итоговые фактические платформы/версии и ограничения записаны в журнале этапов; проверка ARM64 не считается проверкой AMD64.

## Структура

- `backend/app.py`, `http.py` — жизненный цикл, API, аутентификация, ограничение тела и ошибки без входных данных.
- `backend/config.py` — настройки и безопасное создание `.env`.
- `backend/storage.py` — только bootstrap/принадлежность/готовность новой БД; финансовые таблицы — B2.
- `backend/sync_contracts.py` — модели v1, перенесённые с B0.
- `vendor/` — закреплённый SDK и SHA256; `requirements*.lock.txt` — точные зависимости.
- `tests/`, `fixtures/sync-v1/` — автономные и контейнерные проверки.
- `docs/` — контракт, этапы и происхождение извлечённого кода.
